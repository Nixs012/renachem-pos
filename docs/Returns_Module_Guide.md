# Renachem POS: Cashier's Guide to Medicine Returns

This guide explains how to process customer returns and view the returns history.

## 1. How to Process a Return
If a customer brings back a medicine for a refund or exchange, follow these steps:

1.  **Open the Sales Log**: Navigate to **Reports & History** > **Detailed Sales Log**.
2.  **Find the Receipt**: 
    *   Look for the Sale ID (Receipt Number) on the customer's receipt.
    *   Find the matching row in the Sales Log table.
3.  **Click "Return Medicine"**: On the far right of the sale row, click the red **Return Medicine** button.
4.  **Fill the Return Details**:
    *   **Select Item**: Choose the specific medicine being returned.
    *   **Quantity**: Enter how many units are being returned.
    *   **Reason**: Type a short explanation (e.g., "Wrong dosage," "Expired," "Damaged packaging").
5.  **Review Refund**: The system will automatically calculate the **Refund Amount** based on the original sale price.
6.  **Confirm**: Click **Process Return**.
    *   *The system will automatically add the items back into your Inventory.*
    *   *The system will log the refund for accounting.*

---

## 2. How to View Returns History
To see a record of all items that have been returned to the shop:

1.  **Go to History**: Navigate to **Reports & History** > **Returns History**.
2.  **Using the Search Bar**:
    *   Type the **Receipt Number** (e.g., `#105`) into the search bar to see if a specific sale was already returned.
    *   Type the **Medicine Name** to see how often a specific drug is being returned.
3.  **Audit Details**: Each row shows:
    *   **Return Date**: When the items were brought back.
    *   **Refunded**: The exact amount of money that was given back to the customer.
    *   **Processed By**: The name of the staff member who handled the return.

---

## 3. Important Rules for Cashiers
*   **Inventory**: Never manually adjust stock for a return. Always use the **Return Medicine** button so the system stays accurate.
*   **Reasons**: Always provide a clear reason for the return; this helps the Admin track quality issues with suppliers.
*   **Search**: Before processing a return, check the **Returns History** to ensure the customer hasn't already returned the same item.
